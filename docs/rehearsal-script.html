Week −2 · before the academy sees anything

Rehearsal script

All fourteen use cases, walked against the seeded rehearsal academy. Roughly 45 minutes. The point is to find what breaks while it is still cheap — today's smoke test was about instrumentation, not coverage, and it still surfaced two serious bugs.

Grouped by role, not in demo order

The pilot scope runs the use cases in narrative order because that is the story you tell the academy. For a rehearsal that ordering is wrong — it means signing in and out a dozen times. This groups them by who is signed in, which is the same fourteen cases in about a third of the time.

Log, do not fix

When something breaks, write down what you did, what you expected, what happened, and carry on. Stopping to fix things mid-run means the later cases never get walked — and the later ones are precisely the ones nobody has looked at.

Keep the browser console open throughout. Two of today's bugs were only visible there: the assessment failure printed a Postgres error, and a silent telemetry failure prints [telemetry] "<event>" failed:.

Part 1 · Club admin

Sign in as the director

director@rehearsal.trak.dev

UC-01

Academy setup, squads, coach invites

Open the club home, squads and coaches screens. The academy already exists from seeding, so you are checking it reads correctly, then create one new squad by hand.

/club/home · /club/squads · /club/coaches

Look for: does the player count match the squads beneath it? That exact mismatch was a real bug (3bd1507). Three coaches should be listed, one with no squad of their own.

UC-13
Never opened

Squad radar

Band distribution, most improved, players needing attention.

/club/radar

Look for: does it render at all, and are the numbers consistent with the squads? Nobody has opened this since the data was seeded. The scope makes this hypothesis H5 — the director must be able to name one thing here they did not already know.

Part 2 · Coach

Sign in as the U15 coach

coach.u15@rehearsal.trak.dev — the longest stretch, and the one the pilot's load-bearing hypothesis depends on

UC-02

Build the roster

Add three players using Save & add another, then a fourth with Save & finish. Time it with a stopwatch.

/coach/squad/add

Look for: does the age group persist between players? Does focus return to the name field? Does Enter save? The elapsed time is UC-02's real number — the scope calls roster setup the single biggest adoption barrier.

UC-06

Assess a player — full

Move every slider to a different, uneven value. Add a written note. Save.

/coach/assess

Look for: it must save. This is where the card-stats bug lived — decimals into integer columns failed roughly three saves in four, and only when sliders differ. Even values pass every time, which is why it went unnoticed. Session is optional; leave it blank once deliberately.

UC-06

Assess — quick variant

Run quick-assess across the whole squad this time, to the end.

/coach/quick-assess

Look for: do sliders start from each player's previous assessment rather than the midpoint? Time the full run — the target is under 90 seconds per player.

UC-05

Log a match for the squad

Set a date in the past, pick opponent and score, use the bulk select, then expand two players and give them different minutes, goals and cards.

/coach/sessions/quick

Look for: this route now opens the full session screen preset to Match. Confirm per-player detail actually saves — the old screen gave every player identical inputs, which flattened the bands.

UC-09

Award recognition

/coach/recognition → /coach/award

Look for: the award appears on that player's profile afterwards. Check the player side later in Part 3 — a duplicate "Player of the Week" on the passport is a known open observation.

UC-11

Paste fixtures and parse

Use real, messy fixture text — ideally the academy's own, or something equally untidy. Not a clean sample.

/coach/schedule

Look for: how many events come back, and how many are right? Parser accuracy on real text is the whole point; a clean sample proves nothing.

UC-12

Coach assistant

Ask for a session plan. Then ask a follow-up.

/coach/assistant

Look for: does a plan come back with drill diagrams, and is it something you would actually run at training? H6 is about repeat use, so the test is whether the output is good enough to come back to.

Part 3 · Player

Sign in as a player

Pick one you just assessed, so there is fresh data — e.g. nikos.ioannou@rehearsal.trak.dev

UC-03

Signup and squad linking

Rather than reusing a seeded account, create a brand new player with the coach's TRK code from Part 2.

/onboarding/player

Look for: after signup, does the coach's squad show one row for them, not two? Signup now claims the coach's typed roster entry instead of adding a duplicate — this is the check that it works.

Only half-tested

Open the coach's feedback

From the home screen card, not a direct URL.

/player/home → /player/feedback/:id

Look for: the card must appear. It previously rendered only when the assessment carried a written note. Test both — an assessment with a note and one without. Both must reach the screen and produce sensible advice.

UC-04

Parent invite and linking

From the new player account in Part 3, send a parent invite, then redeem it on a fresh parent account.

/parent-invite → /parent/home

Look for: the share sheet appears, the link pre-fills the email, and the child's data shows up after linking. The scope calls this the most fragile step and it is safeguarding-critical.

UC-10
Only half-tested

Child summary, match history, alerts

Only the alerts feed has been opened. Open all three.

/parent/home · /parent/matches · /parent/alerts

Look for: the parent sees bands, never raw numbers, and never the coach's private note. Confirm the assessment and award you created in Part 2 appear here.

Part 5 · Any role

Settings and deletion

UC-14
RPC tested, button not

Delete an account through the UI

Use the new player account from Part 3. Change a setting first, then delete.

/settings → delete account

Look for: the underlying function is verified working — an account with matches, assessments and a linked parent was deleted cleanly. What is untested is the Settings button that calls it. Confirm sign-in afterwards fails, and that the coach's squad no longer shows them.

Then confirm nothing is orphaned

SELECT * FROM squad_duplicate_candidates;
SELECT * FROM pilot_safeguarding_checks;

Both should return zero rows. The first catches duplicate roster entries from signup, the second catches cross-role leakage. Any row is explained in writing before the pilot continues.

After the run

Preserve and review rehearsal data

The legacy purge has been retired because it could delete unrelated records and leave a partial cohort. Current fixtures resume by exact manifest ID; there is no reset command. See the synthetic demo guide. Any cleanup needs an exact reviewed manifest and dependency check.

Then set the pilot window to the real values — starts_on to the pilot start date and org_id to the academy's own organisation, once the director has created it. Leaving org_id pointing at Rehearsal FC makes every cohort metric wrong.
