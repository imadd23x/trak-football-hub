# Departure-safe roster exports — local review proposal

## Problem and intended behavior

U8 requires a removed/transferred coach to lose former-academy access. On the isolated test project, the already-removed synthetic coach freshly authenticated with organization_id NULL: ordinary table reads returned zero former roster/assessment rows, while export_my_account returned both former roster rows and both retained assessments. The privileged export checked author ID but not current roster ownership.

This proposal keeps current authorized coach exports and the caller's own profile available, but excludes former-academy roster, assessment, private-note and award records. It leaves retained records in the academy. Other role branches and the observation-scope switch are unchanged.

## Implementation

One forward migration, generated by the installed Supabase CLI as 20260922091647_restrict_departed_coach_exports.sql, replaces export_my_account. Historical migrations remain unchanged. The four roster-linked collections retain their author-ID condition and also use squad_player_is_mine, the existing current-access predicate. Notes reach that predicate through their assessment. Existing Auth requirement, function security mode and execution grants remain intact.

The SQL test now creates actual academy membership before inserting roster rows, calls remove_coach_from_org as its administrator, and exports as the removed coach. One original roster row is released: removal leaves that status unchanged, so academy ownership matters independently of the departed-status check. A real join_organization into another academy and new authorized records then prove that exclusion does not disable valid exports. This test uses main's joining contract; invitation-only staff-admission composition needs its corresponding invitation-based fixture before a combined release claim.
