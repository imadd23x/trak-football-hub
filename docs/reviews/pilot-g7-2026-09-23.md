# Pilot G7: AI, photos and passport boundary

Scope: guarantee G7 in `MVP Requirements`, with preservation of the manual
J5/J6 coach-message path. Base: canonical main
`496fca21c79db5ea4fb8b640cc1c136b182960f6`. Branch: `codex/pilot-g7-boundary`.
This is local branch evidence, not deployed pilot acceptance.

## Result

- Passport, evolution card, coach assistant, AI review and schedule routes show
  role-guarded “Coming soon” pages. Their feature modules are not imported by
  the application router. Manual coach assessment remains available.
- All three AI edge handlers are inert: non-OPTIONS requests return 403 with
  `PILOT_FEATURE_DISABLED` before reading a body, environment, identity, database,
  quota or provider. Existing hosted JWT verification stays enabled, so a gateway
  may return 401 before the handler for an invalid or missing token.
- Settings and all four profile surfaces use initials. No photo input, signing
  request or stored external image is rendered. Name edits, password reset,
  logout and account deletion remain supported.
- A new CLI-generated migration closes avatar SELECT/INSERT/UPDATE for app
  roles even alongside broad allow policies; denies new or changed nonnull
  profile photo values through direct and SECURITY DEFINER paths; removes app
  access to AI tables; and makes the old AI publisher inert. It preserves manual
  `coach_shared_feedback`, account export/deletion, unrelated buckets and trusted
  cleanup. No historical migration was changed and no retained data was deleted.
- Player feedback reads only published `coach_shared_feedback`, including in
  development. It reports errors with retry, clears old content on identity or
  session changes, and counts an open only after rendering a published message.
