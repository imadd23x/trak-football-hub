## Remaining findings

1. **FS7: preserve published provenance.**
   `20260918120000_coach_approved_feedback.sql:113` still defines `draft_id`
   with `ON DELETE SET NULL`. Deleting a referenced draft succeeds and erases
   the publication's connection to its generated text/model/source history.
   Require an enforcing FK or equivalent concurrency-safe restriction while
   preserving intended account/roster deletion. The independent test accepts
   permission/RLS denial or exactly FK `player_feedback_draft_id_fkey`;
   unrelated errors fail.
2. **FS8: acquire the lock before deciding authority.**
   The publish RPC checks ownership at line 206 and only locks the roster row
   at line 228. The native regression uses the actual admin removal RPC, observes
   the publisher's lock wait, commits removal, then observes unauthorized success.
   Acquire the roster lock first and evaluate authority/consent after the wait.
3. **Repair denial-test discrimination.**
   `supabase/tests/feedback_publication.sql:49` accepts every exception other
   than its own sentinel. Its direct INSERT case also uses an already-published
   roster, allowing uniqueness to mask a missing permission check. Use explicit
   expected errors, a fresh unpublished roster and a populated valid draft for
   isolation tests. The new negative-control command changes SQL only in memory.
4. **Reject unusable model output before saving.**
   `supabase/functions/player-feedback/index.ts:200` validates only a nonempty
   `points` array. Null points, missing point fields, an object-valued title and
   an object-valued encouragement each still produce a stored draft and HTTP 200.
   Validate the complete shared payload contract and handle malformed stored
   values locally in the consumers.

The seven handler controls cover a valid note-free draft, missing authentication,
missing assessment, quota denial, quota failure, player rejection and persistence
