## CI and scope

At this head, `.github/workflows/ci.yml:48` invokes `npm run test:db`.
`package.json:15` invokes the runner without arguments, selecting `--all`.
The second CI invocation uses `--parent-upgrade-review`. Both select only
`parent_invite_security.sql` and `pilot_view_security.sql` in runner lines
52–56. `account_deletion.sql` runs only through `--account-deletion-review` /
`npm run test:db:deletion`. Thus CI does not execute or gate on this new suite.
That matches the PR's stated opt-in design; green ordinary CI would not prove
account deletion works. This review did not inspect hosted run outcomes.

The suite correctly uses the actual `authenticated` role for RPC calls and
resets the role for persistence checks. SQL errors are recorded as failures.
Its limited fixtures do not establish complete data erasure. Existing code
retains coach-name snapshots and consent evidence; that is a retention policy
decision, not anonymization. Existing coach meeting references have no Auth
FK and are not cleaned by the RPC. Avatar cleanup has no call in Settings or
the RPC, and this platform stub cannot verify real Storage object deletion.
These existing residuals remain separate from the F6 repair.

Settings at this candidate already says that some academy history and consent
records may be retained, calls the same no-argument deletion RPC, and checks
its error before signing out. The PR creates no client-contract change. Auth
HTTP/session invalidation and deployed deletion were not tested here; Settings
race fixes are reviewed separately in PR48.
